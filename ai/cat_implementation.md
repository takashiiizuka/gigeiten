# 設計・実装の用語（データ版 2026.09.7）

用意する情報（分野共通）：出力形式、対応環境、コンテンツ、再利用の範囲。基本の内容と追加機能を分けて考えます。

- I-01 ワイヤーフレーム（Wireframe）｜使う場面：装飾前の構成検討。｜注意：完成した見た目を評価する資料ではない。
- I-02 モックアップ（Mockup）｜使う場面：配色・組版・画面の外観確認。｜注意：動作が実装されているとは限らない。
- I-03 プロトタイプ（Prototype）｜使う場面：遷移や作業の検証。｜注意：実装済み機能の範囲と仮の挙動を明示する。
- I-04 デザインシステム（Design system）｜使う場面：複数ページの一貫性。｜注意：部品を並べただけで運用上の合意ができるわけではない。
- I-05 デザイントークン（Design token）｜使う場面：一貫した変更や実装との共有。｜注意：値の名前（blue-500）と用途の名前（エラー色）を分けると管理しやすい。
- I-06 コンポーネント（Component）｜使う場面：ボタンや入力欄の統一。｜注意：同じ見た目でも意味や状態が違う場合がある。
- I-07 バリアント（Variant）｜使う場面：サイズ・強調・状態の整理。｜注意：組み合わせが増えすぎると管理できなくなる。
- I-08 CSS Grid（CSS Grid）｜使う場面：ページ全体や一覧の配置。｜注意：見た目の並べ替えで読み順を崩さない。
- I-09 Flexbox（Flexible box layout）｜使う場面：ナビゲーションや横並びの部品。｜注意：二次元で列を厳密に揃える用途とは使い分ける。
- I-10 コンテナクエリ（Container query）｜使う場面：部品の置き場所に応じた配置。｜注意：親要素に container-type の指定が必要で、要素自身の幅は条件にできない。
- I-11 SVG（Scalable Vector Graphics）｜使う場面：拡大できる図解やグラフ。｜注意：複雑な写真の置き換えには適さない。
- I-12 ラスター画像（Raster image / Bitmap）｜使う場面：写真や質感のある画像。｜注意：拡大時の解像度とファイル量を考える。
- I-13 アスペクト比（Aspect ratio）｜使う場面：画像・動画・図の表示領域。｜注意：枠に合わせて内容を不自然に引き伸ばさない。
- I-14 オブジェクトフィット（Object fit）｜使う場面：切り抜きと全体表示の選択。｜注意：coverでは重要部分が切れる可能性がある。
- I-15 インラインSVG（Inline SVG）｜使う場面：図の色・ラベル・動きを制御する。｜注意：図の意味や代替説明もHTMLと一緒に設計する。
- I-16 プログレッシブエンハンスメント（Progressive enhancement）｜使う場面：多様な環境で使うWeb資料。｜注意：高機能な環境だけで確認して終えない。
- I-17 レイジーロード（Lazy loading）｜使う場面：長いページの初期負荷の軽減。｜注意：最初に必要な主要画像まで遅らせない。
- I-18 プログレッシブディスクロージャー（Progressive disclosure）〔コンテンツの折り畳み〕｜使う場面：初心者と熟練者が使う画面。｜注意：タスクに必要な情報まで発見しにくくしない。
- I-19 アトミックデザイン（Atomic Design）｜使う場面：部品とページの関係の整理。｜注意：5段階の順に作る手順ではなく、部品と全体を行き来して考える見方。
- I-20 オートレイアウト（Auto layout）｜使う場面：文言変更に対応する部品の設計。｜注意：Webの実装が自動的に同じ挙動になるとは限らない。
- I-21 文字の上下の余白の切り詰め（text-box-trim）（Text box trim）〔text-box、text-box-trim、text-box-edge、文字の余白〕｜使う場面：ボタン・見出し・バッジで、文字が上下の中央に見えないずれを揃える。｜注意：2026年8月から主要な最新ブラウザで使えるようになった新しい機能で、古い端末では効かない。効かなくても崩れない余白にし、日本語の書体では実物で確かめる。
