# 関係・工程の図解（データ版 2026.09.5）

用意する情報（分野共通）：登場する要素、要素間の関係、順序、判断条件、担当。線や矢印に何を意味させるかを決めます。

- G-01 フローチャート（Flowchart）〔フロー、手順、分岐〕｜使う場面：業務手順や判断条件の説明。｜注意：分岐条件と到達先を省略しない。
- G-02 スイムレーン（Swimlane diagram）｜使う場面：部門をまたぐ受け渡し。｜注意：レーンが人・部門・システムのどれかを統一する。
- G-03 シーケンス図（Sequence diagram）｜使う場面：APIや人とシステムの対話。｜注意：縦方向の位置は通常、厳密な時間量を示さない。
- G-04 状態遷移図（State diagram）｜使う場面：注文・認証・契約のライフサイクル。｜注意：処理手順と状態そのものを混ぜない。
- G-05 ガントチャート（Gantt chart）｜使う場面：予定や依存関係の管理。｜注意：進捗率と経過時間を混同しない。
- G-06 タイムライン（Timeline）｜使う場面：沿革や実施計画の概要。｜注意：出来事を等間隔に並べたときは、実際の時間差と異なることを注記する。
- G-07 ロードマップ（Roadmap）｜使う場面：戦略と実行の見通し。｜注意：確約日と検討中の見込みを区別する。
- G-08 組織図（Organization chart）〔体制図、指揮系統〕｜使う場面：責任範囲や報告関係の説明。｜注意：非公式な協力関係は別の線などで区別する。
- G-09 ツリー図（Tree diagram）｜使う場面：分類や構成の整理。｜注意：一つの子が複数の親を持つ場合は単純な木にならない。
- G-10 マインドマップ（Mind map）｜使う場面：発想の整理。｜注意：位置や枝の長さに数量の意味があるとは限らない。
- G-11 コンセプトマップ（Concept map）｜使う場面：複雑な知識の関係を説明する。｜注意：線に意味を付けず単なる単語の羅列にしない。
- G-12 ネットワーク図（Network diagram）｜使う場面：組織間連携やシステム接続。｜注意：配置の近さに意味があるかを明記する。
- G-13 ベン図（Venn diagram）｜使う場面：条件の組み合わせ。｜注意：領域面積が数量に比例するとは限らない。
- G-14 ER図（Entity–relationship diagram）｜使う場面：データ構造の説明。｜注意：矢印・端の記号の表記法を統一する。
- G-15 クラス図（Class diagram）｜使う場面：ソフトウェアの静的な構成。｜注意：データベースの表と必ず一対一ではない。
- G-16 C4モデル（C4 model）｜使う場面：相手の知識に合わせたシステム構成図。｜注意：C4のコンテナはDockerだけを意味しない。
- G-17 レイヤー図（Layered diagram）｜使う場面：技術・組織・サービスの構造。｜注意：上下の並びが依存・包含・優先度のどれを表すかを明示する。
- G-18 サイクル図（Cycle diagram）｜使う場面：改善活動や定期運用。｜注意：回るだけで自動的に良くなると誤解させない。
- G-19 特性要因図（フィッシュボーン）（Fishbone / Ishikawa diagram）〔フィッシュボーン、特性要因図、石川ダイアグラム、魚の骨図〕｜使う場面：原因の仮説を広げる。｜注意：図に書いた要因が真の原因と証明されたわけではない。
- G-20 親和図（Affinity diagram）〔KJ法、親和図法〕｜使う場面：定性調査やアイデアの整理。｜注意：少数意見や分類しにくい内容を消さない。
- G-21 2×2マトリクス（Two-by-two matrix）〔四象限、2×2マトリックス、2x2マトリクス〕｜使う場面：選択肢の分類や優先度。｜注意：軸・高低・境界の意味を明示する。
- G-22 比較マトリクス（Comparison matrix）｜使う場面：製品・案・施策の比較。｜注意：比較条件と評価基準を揃える。
- G-23 カスタマージャーニーマップ（Customer journey map）〔CJM、顧客体験、カスタマージャーニー〕｜使う場面：体験の課題を見つける。｜注意：実際の調査と仮説を分ける。
- G-24 サービスブループリント（Service blueprint）〔顧客、裏側〕｜使う場面：顧客接点と社内業務の改善。｜注意：見える活動と見えない活動の境界を示す。
- G-25 共感マップ（Empathy map）｜使う場面：調査内容から利用者理解を共有する。｜注意：本人が話した事実と推測を混ぜない。
- G-26 サイトマップ（Sitemap）｜使う場面：情報設計やページの整理。｜注意：画面内の操作フローとは別の図。
- G-27 ピラミッドストラクチャー（Pyramid structure (Pyramid Principle)）〔ピラミッド原則、ピラミッド構造〕｜使う場面：論理的な説明や提案。｜注意：図が三角形なら論理が成立するわけではない。
- G-28 SCQA（Situation, Complication, Question, Answer）｜使う場面：問題と提案の導入。｜注意：説明上の筋書きのために事実を誇張しない。
- G-29 ロジックツリー（Logic tree / Issue tree）｜使う場面：検討すべき論点の整理。｜注意：分解軸の混在と重複・抜けを確認する。
- G-30 SIPOC（Suppliers, Inputs, Process, Outputs, Customers）｜使う場面：業務の全体像と境界の共有。｜注意：詳細な分岐フローとは目的が異なる。
- G-31 BPMN（Business Process Model and Notation）｜使う場面：組織間で共有する業務モデル。｜注意：任意の矢印図にBPMNという名前を付けない。
- G-32 ハーヴェイボール（Harvey balls）〔ハーベイボール、ハービーボール〕｜使う場面：評価表の簡潔な一覧。｜注意：数値の実測割合か、順序尺度の評価かを明示する。
- G-33 ビフォー・アフター（Before–after comparison）〔ビフォーアフター図、ビフォーアフター〕｜使う場面：改善点の説明。｜注意：有利な例だけ選ぶ、尺度を変えるなどの比較を避ける。
- G-34 ストーリーボード（Storyboard）｜使う場面：利用シーンや映像の計画。｜注意：登場人物の行動が、調査で確かめた事実か仮説かを区別する。
- G-35 商流図（Commercial flow diagram）｜使う場面：販売経路や仲介者、取引と配送の違いを説明する。｜注意：商流・物流・金流を同じ矢印で混同しない。矢印の意味を凡例に示す。統一された唯一の記法がある図ではない。
- G-36 KPIツリー（KPI tree）｜使う場面：売上などの目標と、追跡する指標の関係を整理する。｜注意：算式として成立する分解と、影響するという仮説を区別する。対象期間・単位・母集団を揃える。
- G-37 シェブロン工程図（Chevron process）〔矢羽根（シェブロン）、矢羽根、シェブロン〕｜使う場面：調査から公開までのフェーズを短く説明する。｜注意：矢羽根の長さを期間や量と読み取らせない。分岐・戻り・担当の整理には別の図が適する。
- G-38 WBS（作業分解構成図）（Work breakdown structure）〔WBS〕｜使う場面：必要な成果物と作業範囲の抜け・重複を確認する。｜注意：工程順や日程そのものではない。末端の作業パッケージの内容を定義し、ガントチャートとは区別する。
- G-39 ポジショニングマップ（Positioning / Perceptual map）〔ポジショニング、知覚マップ、パーセプチュアルマップ、位置付け〕｜使う場面：競合の中での特徴や、顧客にどう認識されているかを比較する。｜注意：軸の選び方・位置の根拠を示す。知覚マップなら顧客調査等に基づく。空白が需要の存在を意味するとは限らない。
- G-40 人物相関図（People relationship map）｜使う場面：関係者の協力・相談・報告などのつながりを整理する。｜注意：線が何を表すか、方向があるかを明記する。距離や大きさに意味を持たせるなら定義する。関係を推測で確定しない。
- G-41 番号付きの画面注記（Numbered callouts on screenshots）〔注釈つきスクリーンショット、画面キャプチャの注記、番号付きの印、操作手順の図〕｜使う場面：業務システムやアプリの操作手順書・マニュアル。｜注意：説明文は画像に書き込まず、本文の手順に置く。印は短い番号にし、押す箇所と押さない箇所は色だけでなく線の種類でも区別する。
